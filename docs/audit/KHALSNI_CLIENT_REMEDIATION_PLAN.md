## QA fixture operation

`python manage.py seed_client_audit_qa` requires `DJANGO_DEBUG=True` and an uncommitted `KHALSNI_QA_PASSWORD` of at least 12 characters. It creates six namespaced QA accounts, a public QA service and mandatory PDF definition, provider-service links, four distinct scenario orders, an internal note, and upload/final-result PDFs. Rerunning it preserves the same four scenario records and checks their expected states. If a scenario has progressed or drifted, the command fails instead of silently treating it as a clean baseline. `--rebuild-owned` explicitly recreates only those four marker-matched QA orders and their document records; it refuses a scenario with payment, invoice, or payout records. No customer audit reference order or unrelated order is targeted.

The original `seed_initial_data.py` had a global `Order.objects.exists()` guard, so arbitrary existing orders could prevent its corrected demo orders from appearing. The namespaced QA command is the deterministic acceptance fixture and does not depend on that guard. It should be run on an isolated test database for a repeatable browser journey.
